# HTTP Traffic Analysis Using Wireshark

## 1. Overview
A hands-on network traffic analysis project using Wireshark to understand HTTP communication generated by my own system.

## 2. Objectives
- Capture HTTP traffic using Wireshark.
- Filter and identify HTTP packets.
- Analyze HTTP GET requests, headers, and URLs.
- Examine HTTP responses and status codes.
- Inspect HTTP payload data and understand client-server communication.
- Develop basic network traffic analysis and troubleshooting skills.

## 3. Tools & Environment
- **Tool:** Wireshark
- **Browser:** Mozilla Firefox
- **Operating System:** Kali Linux
- **Traffic Source:** My own system

## 4. Methodology
1. Generated network traffic by browsing websites using Firefox.
2. Captured the traffic through Wireshark.
3. Applied the `http` display filter to identify HTTP packets.
4. Inspected HTTP request packets to identify the request method, URL, host, and User-Agent.
5. Examined HTTP response packets to identify status codes, content type, content length, and other response headers.
6. Used **Follow → TCP Stream** to inspect the complete HTTP request-response exchange and view the response body.

## 5. Analysis & Observations

### 5.1 HTTP GET Request
Inspected an HTTP GET request sent to `detectportal.firefox.com`.

**Information observed:**
- **Request Method:** GET
- **Requested Resource:** `/success.txt?ipv6`
- **Host:** `detectportal.firefox.com`
- **HTTP Version:** HTTP/1.1
- **User-Agent:** Mozilla Firefox 140.0 on Linux x86_64
- **Connection:** Keep-Alive

The request is consistent with Firefox's connectivity-check mechanism.

### 5.2 HTTP Response Analysis
Examined the server's response to the HTTP request.

**Information observed:**
- **Status Code:** 200 OK
- **Content-Type:** `text/plain`
- **Content-Length:** 8 bytes
- **Server Header:** Varnish
- **Connection:** Close

The `200 OK` status indicates that the request was successfully processed.

### 5.3 TCP Stream Analysis
Used **Follow → TCP Stream** to view the HTTP conversation between the client and server.

**Observations:**
- The HTTP GET request and corresponding response were visible in the same stream.
- Request and response headers could be examined together.
- The response body contained the text `success`.
- The stream provided a clearer view of the application-layer communication.

## 6. Key Learnings
- Capturing and filtering HTTP traffic in Wireshark.
- Understanding HTTP request and response structures.
- Identifying request methods, headers, and response status codes.
- Using TCP stream analysis to reconstruct application-layer conversations.
- Understanding how browsers perform connectivity checks.

## 7. Privacy & Scope
- Raw packet capture files are intentionally excluded to protect potentially sensitive network information.
- The investigation is limited to traffic observed during the capture period.
- This project is intended for educational purposes and does not represent a complete security audit.

## 8. Conclusion
This project provided practical experience in capturing and analyzing HTTP traffic using Wireshark. By examining HTTP requests, responses, and TCP streams, I gained a better understanding of client-server communication and basic network troubleshooting.
